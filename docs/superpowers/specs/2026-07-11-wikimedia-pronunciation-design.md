# 词迹 v1.2 Wikimedia 真人发音设计规格

日期：2026-07-11

## 1. 目标

为“词迹”增加以 Wikimedia Commons / Wiktionary 真人录音为主的发音能力，解决部分 HarmonyOS 设备中系统语音无声、合成音频机械感明显的问题，同时保留现有本地合成音频和系统语音作为降级方案。

本版本目标不是消除所有音频文件格式，而是将主要发音来源从批量合成音频切换为经过审核的真人录音。

## 2. 已确认的产品决策

1. 播放顺序采用：Wikimedia 真人录音 → 当前本地合成音频 → 系统语音。
2. 当前 131 个单词使用人工审核后的固定映射。
3. 后续新增词采用混合模式：自动搜索候选，用户审核后保存为固定映射。
4. 新增词先正常导入，再在“词库 → 待审核发音”中集中处理。
5. 真人录音采用按需缓存，并支持手动下载当日词包的真人发音。
6. 卡片仅显示“真人发音 · Wikimedia”，点击后展开作者、许可证和来源页。
7. 英式和美式优先分别寻找真人录音，不要求所有词都具备双口音。
8. 缺少某一口音时，不使用另一口音冒充，直接进入降级链路。

## 3. 版本范围

### 3.1 本版本包含

- 当前 131 词的英式 / 美式真人录音固定映射文件。
- Wikimedia / Wiktionary 候选搜索服务。
- 待审核发音页面。
- 真人录音播放与降级链路。
- IndexedDB 中的用户审核结果。
- Cache Storage 中的真人录音缓存。
- “下载今日真人发音”功能。
- 录音作者、许可证及来源页展示。
- 设置页中的发音来源、口音、缓存和失败提示选项。
- 旧数据迁移与兼容。

### 3.2 本版本不包含

- 商业真人词典 API。
- 用户自行上传录音。
- 自动将所有候选批量确认为正式发音。
- 后台服务器或 API 密钥。
- 自动删除现有本地合成音频。
- 对真人录音进行二次编辑、拼接或重新发布。

## 4. 总体架构

系统拆分为以下独立模块：

1. `PronunciationResolver`
   - 根据单词、口音和设置决定播放来源。
   - 不负责具体网络查询或 UI 展示。

2. `WikimediaMappingStore`
   - 读取应用内置的 131 词固定映射。
   - 读取用户在 IndexedDB 中保存的审核结果。
   - 用户审核结果优先级高于内置映射。

3. `WikimediaSearchService`
   - 查询 Wiktionary 词条关联录音和 Commons 候选文件。
   - 解析地区、作者、许可证、文件页及可播放 URL。
   - 仅生成候选，不自动批准。

4. `PronunciationReviewStore`
   - 保存候选、审核状态、拒绝记录和缺失标记。
   - 支持英式和美式独立审核。

5. `AudioPlaybackController`
   - 负责停止上一条、播放当前条、超时、取消和降级。
   - 保证任意时刻只有一个单词正在播放。

6. `PronunciationCacheService`
   - 负责真人录音的按需缓存、批量下载、空间统计和清理。
   - 清理缓存不影响单词和学习进度。

7. `AttributionPanel`
   - 展示作者、地区、许可证、来源页面和缓存状态。

8. `PronunciationReviewPage`
   - 集中处理新增词的英式 / 美式候选。

## 5. 播放链路

### 5.1 真人词典优先模式

播放顺序如下：

1. 已缓存且审核通过的 Wikimedia 真人录音。
2. 在线且审核通过的 Wikimedia 真人录音。
3. 当前本地合成音频。
4. 系统语音。
5. 显示“发音暂不可用”。

任一层成功开始播放后，立即停止后续降级。

### 5.2 口音规则

- 英式设置只读取英式真人映射。
- 美式设置只读取美式真人映射。
- 未标明地区的英语录音仅作为审核候选，不自动映射到英式或美式。
- 某一口音缺失时，不允许借用另一口音的真人录音。

### 5.3 并发与取消

- 点击新单词时立即停止前一个音频。
- 取消前一个尚未完成的网络请求。
- 多次快速点击时只保留最后一次播放请求。
- 同一播放请求只能触发一次降级链路。

### 5.4 超时

| 阶段 | 超时 | 失败后 |
|---|---:|---|
| 读取真人录音缓存 | 1 秒 | 请求在线录音 |
| 在线 Wikimedia 录音 | 6 秒 | 本地合成音频 |
| 本地合成音频 | 4 秒 | 系统语音 |
| 系统语音 | 3 秒内未开始 | 标记不可用 |

## 6. 数据结构

### 6.1 正式发音记录

```ts
type PronunciationStatus =
  | "unreviewed"
  | "approved"
  | "rejected"
  | "missing";

type PronunciationAccent = "en-GB" | "en-US" | "unknown";

type PronunciationRecord = {
  accent: PronunciationAccent;
  status: PronunciationStatus;

  audioUrl?: string;
  compatibleAudioUrl?: string;
  filePageUrl?: string;

  author?: string;
  licenseName?: string;
  licenseUrl?: string;

  sourceFileName?: string;
  durationSeconds?: number;

  reviewedAt?: string;
  mappingVersion?: number;
};

type WordPronunciations = {
  british?: PronunciationRecord;
  american?: PronunciationRecord;
};
```

### 6.2 候选记录

```ts
type WikimediaCandidate = {
  word: string;
  accent: PronunciationAccent;
  audioUrl: string;
  compatibleAudioUrl?: string;

  filePageUrl: string;
  fileName: string;

  author: string;
  licenseName: string;
  licenseUrl?: string;

  durationSeconds?: number;
  source: "wiktionary" | "commons-search";
};
```

### 6.3 读取优先级

```text
用户审核结果
→ 内置 131 词映射
→ 待审核候选
→ 无真人录音
```

待审核候选不会进入正式播放链路。

## 7. 当前 131 词固定映射

内置映射文件：

```text
data/wikimedia-pronunciations.json
```

每个口音必须单独满足以下条件后才能标记为 `approved`：

- 录音确实朗读目标单词；
- 与目标词形匹配；
- 地区标注足以判断英式或美式；
- 音频可在目标浏览器播放，或存在兼容转码地址；
- 录音时长合理；
- 没有完整例句、音乐、多人对话或明显噪声；
- 作者和许可证信息完整；
- 来源文件页可以打开。

无法满足条件时，将对应口音标记为 `missing`，由本地合成音频兜底。

## 8. 新增词与待审核流程

### 8.1 导入后处理

```text
导入词包
→ 单词立即进入词库
→ 有正式映射的直接使用真人录音
→ 无正式映射的进入“待审核发音”
→ 未审核期间使用本地合成音频兜底
```

### 8.2 候选搜索

搜索步骤：

1. 对单词进行标准化。
2. 查询 Wiktionary 词条关联发音。
3. 查询 Commons 文件候选。
4. 提取音频 URL、兼容 URL、地区、作者、许可证和文件页。
5. 对英式和美式候选分别排序。
6. 每种口音最多返回 5 条候选。

标准化规则：

- 转为小写；
- 去除首尾空格；
- 保留连字符和撇号；
- 词组作为整体查询；
- 相同查询结果短期缓存，避免重复请求。

### 8.3 候选排序

```text
Wiktionary 词条明确关联音频
→ 文件名与目标单词完全匹配
→ 地区明确匹配当前口音
→ 音频时长合理
→ 授权信息完整
→ 其他英语录音
```

### 8.4 排除规则

必须排除：

- 完整例句；
- 明显属于其他语言；
- 文件名或词条明显对应其他词形；
- 多人对话；
- 音乐背景；
- 严重噪声；
- 授权信息缺失；
- 浏览器无法播放且不存在兼容地址。

### 8.5 审核页面

入口：

```text
词库 → 待审核发音
```

筛选项：

- 今日词包；
- 全部待审核；
- 仅缺英式；
- 仅缺美式；
- 已标记缺失。

单条操作：

- 试听；
- 确认使用；
- 换一条；
- 拒绝候选；
- 标记缺失；
- 跳过。

快捷操作：

- 确认英式并进入下一词；
- 确认美式并进入下一词；
- 两个口音均确认；
- 跳过。

不提供“全部自动确认”。

## 9. 缓存与离线

### 9.1 按需缓存

- 第一次成功播放审核通过的真人录音后自动写入缓存。
- 再次播放时优先读取缓存。
- 缓存键包含单词、口音、文件标识和映射版本。
- 映射版本变化后旧缓存失效。

### 9.2 下载今日真人发音

词包详情页提供：

```text
下载今日真人发音
```

下载前展示：

- 可下载真人录音数量；
- 缺少真人录音数量；
- 预计占用空间；
- 当前下载口音：英式、美式或双口音。

下载行为：

- 只下载 `approved` 录音；
- 支持暂停和继续；
- 单个文件失败不终止批量任务；
- 完成后显示成功数、失败数和缺失数。

### 9.3 缓存管理

设置页显示：

- 真人录音缓存占用；
- 已缓存单词数量；
- 清除真人录音缓存按钮。

清除缓存不会删除：

- 单词；
- 词包；
- 认识 / 模糊 / 不认识记录；
- 复习计划；
- 用户审核结果。

## 10. 署名与授权展示

卡片默认只显示：

```text
真人发音 · Wikimedia
```

点击后展开：

- 录音作者；
- 英式、美式或地区未标明；
- 许可证名称；
- 许可证链接；
- Wikimedia 文件来源页；
- 本地缓存状态。

对于缺少作者、许可证或来源页的候选，不允许确认使用。

## 11. 设置页

新增或调整以下设置：

### 发音来源

- 真人词典优先；
- 本地发音优先；
- 仅系统语音。

### 口音

- 英式；
- 美式。

### 缓存

- 首次播放后自动缓存：默认开启；
- 真人录音缓存管理；
- 下载今日真人发音入口。

### 发音失败提示

- 开启；
- 关闭，默认关闭。

关闭时只更新按钮状态，不显示打断学习的弹窗。

## 12. 播放状态反馈

发音按钮需要支持以下状态：

- 正在加载真人发音；
- 正在播放真人发音；
- 正在使用备用发音；
- 发音暂不可用。

状态变化不得阻塞卡片切换、评分或沉浸模式操作。

## 13. 数据迁移

v1.2 首次启动时：

- 保留现有词库；
- 保留每日词包；
- 保留认识、模糊、不认识记录；
- 保留复习计划；
- 保留英式 / 美式选择；
- 保留现有本地合成音频作为备用；
- 导入 131 词真人录音映射；
- 新字段缺失时按默认值补全；
- 不自动删除旧音频和旧设置。

迁移失败时必须回滚或跳过新字段，不得破坏已有学习数据。

## 14. 错误处理

### 14.1 网络错误

- Wikimedia 查询失败时保留待审核状态。
- 已审核录音在线加载失败时进入本地音频降级。
- 不因单个候选失败阻塞其他候选。

### 14.2 数据错误

- 映射缺少关键授权字段时视为无效映射。
- IndexedDB 中的用户记录损坏时忽略该条并回退内置映射。
- 缓存文件损坏时删除该缓存项并重新请求在线录音。

### 14.3 播放错误

- `play()` 被浏览器拒绝时保留用户手势上下文并尝试备用音频。
- 不允许重复触发多条系统语音。
- 每次播放完成或失败后必须清理计时器、网络请求和音频对象。

## 16. 验收标准

1. Mate X7 点击已审核单词能够听到真人录音。
2. 真人录音失败时能够自动切换本地备用音频。
3. 英式和美式切换后不会串用错误口音。
4. 某一口音缺失时不会借用另一口音冒充。
5. 点击下一单词时前一个发音立即停止。
6. 多次快速点击只播放最后一个单词。
7. 已播放真人录音再次打开时优先读取缓存。
8. 离线状态下已下载录音可以正常播放。
9. 每条正式真人录音都能查看作者、许可证和来源页。
10. 清除音频缓存不会删除学习进度。
11. 新增词可以进入“待审核发音”。
12. 未审核候选不会自动用于正式学习。
13. 批量下载中单个文件失败不会终止全部任务。
14. v1.1 用户升级后原有词库和掌握记录完整保留。
15. 发音失败提示关闭时不会弹窗打断学习。

## 18. 完成定义

只有在以下条件同时满足时，才可以宣布 v1.2 真人发音版本完成：

- 所有验收标准通过；
- 预览部署成功；
- Mate X7 实机确认能够听到至少一条审核通过的真人录音；
- 131 词固定映射中的每条已批准录音都具备完整授权元数据；
- 降级链路在真人录音失败时可正常工作；
- 旧学习数据未丢失。
